🧩 Projet 10 -

MyContent : système de recommandation d’articles

Contexte MVP :
MyContent est un moteur de recommandation pour portail d’actualités, destiné à proposer un Top-5 personnalisé à chaque lecteur à partir de ses interactions récentes.

Objectif :
Valider un pipeline de recommandation hybride mêlant contenu et collaboratif, prêt à être exposé via une architecture serverless.

🧭 Vue d’ensemble du projet

Le projet MyContent vise à fournir des recommandations pertinentes dans un cadre MVP :

  • Objectif produit : maximiser l’engagement via un Top-5 d’articles pertinents.
  • User story clé :
« En tant qu’utilisateur de l’application, je vais recevoir une sélection de cinq articles. »

🧠 Panorama des approches

📌 Content-Based Filtering

  • Compare les articles via leurs embeddings
  • Recommande des contenus proches sémantiquement
  • Particulièrement utile en cold-start utilisateur

🤝 Collaborative Filtering

  • Apprend des patterns d’interaction entre utilisateurs et articles
  • Exploite les co-consommations implicites
  • Performance liée à la densité des interactions

📌 Modèle Content-Based retenu

Embeddings d’articles + similarité cosinus

🧠 Principe

  • Embeddings d’articles (250 dimensions)
  • Normalisation + similarité cosinus
  • Stratégie last_item pour générer les candidats

📈 Résultats observés

  • precision@5 = 0.001104
  • recall@5 = 0.005522
  • ndcg@5 = 0.003815
  • coverage@5 = 0.6565

✅ Couverture correcte, mais qualité de ranking en retrait face aux modèles collaboratifs.

🤝 Modèle Collaborative Filtering retenu

SVD++ sur interactions implicites

🧠 Principe

  • SVD++ entraîné via Surprise
  • Exploit des signaux implicites de lecture
  • Pondération de session pour refléter l’engagement
  • Usage de la librairie surprise

📉 Limites observées

  • SVD++ basic : precision@5 = 0.000278
  • SVD++ pondéré : precision@5 = 0.001630
  • recall@5 = 0.008150 (pondéré)
  • coverage@5 = 0.447400 (pondéré)
  • RMSE : 0.7210 (basic) vs 1.5824 (pondéré)

⚠️ Le collaboratif pondéré dépasse le content-based en recall/NDCG, mais reste sensible à la sparsité et au cold-start.

⭐ Rating implicite

Transformation des clics en signal supervisé exploitable par Surprise

🧮 Calcul

  • Score implicite :
    implicit_score = 3 × log1p(click_count) + 1 × log1p(avg_session_size)
  • Limitation des valeurs extrêmes :
    clip au percentile 95
  • Mise à l’échelle finale :
    min–max scaling → [1 ; 5]

💡 Explications

  • Plus un utilisateur clique souvent sur un article, plus son intérêt est considéré comme fort
  • Les longues sessions renforcent le signal d’engagement
  • La normalisation empêche quelques utilisateurs très actifs de dominer l’apprentissage

✅ Ce rating implicite permet d’entraîner des modèles collaboratifs (SVD / SVD++) en l’absence de notes explicites.

🧬 Modèle hybride

Fusion rangée : SVD++ pondéré + contenu

⚙️ Principe

  • Fusion par rang : 60% collaboratif / 40% contenu
  • Combine similarité de contenu + préférences implicites
  • Recommandation Top-5 stable

📈 Résultats

  • precision@5 = 0.001788
  • recall@5 = 0.008940
  • ndcg@5 = 0.005382
  • coverage@5 = 3.2502

✅ Meilleur compromis qualité/couverture → retenu pour le MVP.
⚠️ Limite : dépendance à deux sources (modèle SVD++ + embeddings).

🧱 Architecture technique

🧮 PCA

Réduction de dimension pour la production

🔍 Principe

  • Embeddings réduits de 250 → 32 dimensions
  • Variance expliquée : 84,29%
  • Artefacts PCA sauvegardés pour l’inférence

🚀 Impact

  • Réduction des coûts de stockage Azure
  • Chargement plus rapide des embeddings
  • Amélioration de la latence d’inférence

🖥️ Interface utilisateur

MVP Flask connecté à l’API Azure

🧭 Fonctionnement

  • Appel au endpoint Azure Function
  • Affichage des Top-5 recommandés
  • Onglet Similar Articles via /article-similarity
  • Onglet Active users qui donne un top 10
  • Documentation interactive via /docs

✅ L’interface sobre de la première version du MVP remplie pleinement ses fonctions

✅ Conclusion

Synthèse des choix techniques

  • Le content-based conserve une couverture correcte mais une qualité de ranking plus faible.
  • Le collaboratif SVD++ pondéré dépasse le content-based en recall/NDCG.
  • Le modèle hybride offre le meilleur compromis qualité/couverture et le meilleur ranking global.
  • ✅ Modèle retenu pour le MVP : SVD++ pondéré + contenu (60/40).
